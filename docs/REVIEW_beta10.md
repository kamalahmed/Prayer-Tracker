# beta.10 / Phase 18 — layout and data-protection self-review

## Widget diagnosis and changes
- The beta.9 root occupied the whole cell, but its background was deliberately applied only to a wrap-height inner panel. `SizeMode.Exact` was already present; it did not resize the panel or its fixed typography. The result was a small panel floating in a much taller launcher selection.
- Retain Exact sizing and observed Room/settings flows. Default to a cell-filling panel with independent fill/wrap, overall content scale, 0–24 dp outer margin and existing inner horizontal/vertical padding and spacing. Fit typography/icons/hit-area dimensions from the actual allocation. Small one-row prayer widgets omit the header rather than making every prayer unreadable.
- Tasbih's declared 180×220 dp resize minimum effectively prevented a short placement; its preview pointed at `widget_preview_next`. It now has a 2×2 default, a 110×48 dp shrink minimum, two-axis resize, a counter-specific previewLayout/previewImage and responsive square/wide arrangements. Wide count/target text fits without truncation. Configuration uses the actual Glance composition, counter data and adjustable preview dimensions.
- Both mode uses equal-weight centered columns, distinct primary times and smaller/muted Iqamah labels/times; no divider or A/I prefixes. The wide header countdown is constrained within its row instead of allowing AndroidRemoteViews to consume the row. The large table has three centered, equally weighted columns. Visual self-review found hidden zero-height dashboard rows; compact two-line secondary times and removal of a duplicate header line now preserve Isha. A native-pixel regression also caught an opaque white tint under highlights; direct ARGB backgrounds retain contrast. Tracker and Next + streak have Off/Above/Below timing controls independent of Start/Iqamah/Both.
- Android owns grid allocation and host padding: existing placements retain their reserved cells after an upgrade. Resize with the launcher handles, or re-add for new defaults. App padding/scale settings cannot shrink Samsung's grid itself.

## Backup and logging safety
- Settings > Backup & restore: SAF JSON export/import; versioned, explicitly typed format, seven whitelisted Room tables, app/widget preferences, counter feedback/volume-key preferences, updater user choices (not installer consent/cache), and selected private custom audio. Streaks are derived from logs, not discarded or independently reconstructed from a summary.
- Parse/validate the complete input before mutation: format/database version, required containers/columns, types, keys, dates, enum values, nonnegative bounded counts, references and preference types. Unknown future versions, malformed containers and SQL-shaped inputs are refused. Legacy Room v1–3 snapshots are upgraded in memory; v3 missing counter fields get defaults. Current input is bounded to 32 MB / 250,000 rows; custom audio to 16 MB. Exports exceeding these bounds fail visibly instead of silently omitting history.
- Every accepted restore first commits and rereads a full atomic safety snapshot. Replace and Merge writes use a Room transaction. An injected insert failure after DELETE verifies rollback of both earlier inserts and deletes. Preferences are compensated from the safety image on failure. Once confirmed, restore and its post-commit alarm/widget reconciliation complete non-cancellably rather than being interrupted by navigating away. A query-latched cancellation test reproduces closing the screen during the transaction and verifies completion. DB and DataStore are separate storage engines: an abrupt process/power failure between their commits may require restoring the retained safety snapshot; no claim of a cross-engine atomic commit is made.
- Merge is idempotent: newer prayer marks win; daily counts/pages/minutes and Qada debt take the maximum, not a sum; distinct Qada events survive numeric ID collisions and identical events do not double; current item definitions/settings win. Replace is explicitly labeled destructive and requires preview confirmation; the old data stays available in its safety snapshot.
- Seven rolling daily local JSON files, plus ten independent pre-import/pre-migration recovery points. Startup makes today's missing snapshot and a daily WorkManager job refreshes it. Production migrations are wrapped so the snapshot is written before SQL changes; snapshot failure aborts migration. Snapshots use AtomicFile and verify the committed content before permitting mutation. Optional SAF folder export uses a persistable user-selected grant and unique documents, never overwriting a previous external copy.
- Restores cancel old Quran reminder IDs, reschedule prayer/Iqamah/Quran/Qada alerts and refresh widgets. Platform failures are caught and shown as a post-restore warning, not falsely reported as loss of restored data.
- Android allowBackup was already true. Rules are now explicit allowlists for tracker DB/WAL, DataStore, snapshots, audio and backup/counter metadata, for cloud and device transfer. Cache/update APKs, installer state, diagnostics and WorkManager DB are not selected.

## Verification and limitations
- Real Glance -> RemoteViews -> Android Views -> native Skia PNG tests cover every widget at multiple sizes, fill vs wrap, margins/transparency, counter content/target clipping, timing column alignment, scale and tick positioning. They are not hand-drawn mockups. Render output: `/workspace/prayer-app-release/widget-renders/beta10/`.
- Backup tests cover all-table/settings/audio round trips, corrupt and future input, older schema, merge repetition, transaction failure, navigation cancellation, preference type confusion, malformed containers, seven-file retention, actual pre-migration snapshot capture and Backup screen confirmation.
- Original six JPG paths supplied for this task were not materialized on the box when checked; only an APK was present in that attachment directory. Source diagnosis and actual generated renders were used instead.
- No Galaxy/One UI hardware run, real document-provider permission/uninstall recovery, installed beta.9 upgrade, or Android cloud restore was performed. WorkManager can be delayed by Android. Local files are deleted on uninstall/clear-data; only a separately exported document/folder copy survives. Android cloud backup depends on the device backup setting, transport and quota. External ringtone grants and launcher placements may need reconfiguration. Backup JSON is personal, unencrypted data; the screen says so. Google Drive sign-in is intentionally not added.
